# Honest xP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the site's xP our own v2 forecast with a visible "why" breakdown, re-run the backtest without the leaked FPL archive numbers, and rewrite the project's story to the corrected result.

**Architecture:** Clean FPL predictions only enter the database when saved before the deadline (collector). The backtest drops the archive's FPL numbers, adds a leak check and a fair current-season FPL comparison, and picks among our own methods. `v_xp_next` loses its FPL branch. A new v2 breakdown view feeds per-card data that the page draws as a breakdown with an unmissable bonus warning.

**Tech Stack:** Python 3.13, Streamlit 1.66.0, SQLite views (`fpl/sql/*.sql`), vanilla JS page `fpl/ui/team_sheet/index.html`, pytest + node harness.

**Spec:** `docs/2026-10-26-honest-xp-design.md` (approved 26 Oct 2026). Mockup: `.superpowers/brainstorm/17936-1793051058/content/xp-breakdown-v2.html` (local).

## Global Constraints

- No new dependencies; Streamlit stays 1.66.0; no JS build tools.
- Every number comes from SQL views / analysis code; the page only displays.
- The reload guard in `app.py` (`code_signature`, `reload_if_code_changed`) must keep working; don't change it.
- FPL's number is never used as the site's xP anywhere (cards, panel, xP next 3, 👍 options, SELL, grades, projected).
- Copy, verbatim: "⚠ Bonus points not included — top attackers often earn 1–2 more a game than this shows."; "Bonus points"; "not counted"; "Also not counted: cards, own goals."; "Not enough data for a breakdown — using the simpler model."; "2 games"; "too early to call".
- Breakdown parts must add up to the headline next-GW xP (within 0.05 per part rounding).
- Under 5 clean gameweeks, the FPL comparison is labelled "too early to call"; docs call GW8 "an early sign from one gameweek".
- Same dark style; works at ≈400px wide.
- Tests: `.venv/bin/pytest -q` (290 before this build) stay green; tests set `FPL_RELOAD_GUARD=0` via `tests/conftest.py` already.
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Don't push in the hours before a deadline (GW9: 2026-10-31 11:00 UTC).

## Review Focus

1. **A player with no v2 value** (new signing, no history): xP falls back to v1, and the panel shows the fallback sentence, with no breakdown. Tests in Tasks 3 and 5.
2. **Double gameweek:** the breakdown sums both fixtures, shows "2 games", and the parts still add up. Tests in Tasks 4 and 5.
3. **Blank gameweek:** xP is 0, and the breakdown says "No game this gameweek" instead of drawing empty rows. Tests in Tasks 4 and 5.
4. **Position rules:** goalkeepers have no DefCon row and forwards have no clean-sheet row. Test in Task 5.
5. **A snapshot saved after the deadline:** its `ep_pre` stays NULL, so it's excluded from the FPL comparison and counted as excluded. Tests in Tasks 1 and 2.

### Task 2: Backtest without leaked numbers, plus a leak check

**Files:** Modify `fpl/backtest.py`. Test `tests/test_backtest.py`.

**Interfaces — Produces:**
- `METHODS = ("model", "last5_avg", "v2")` for the archive tables (1-gameweek and 3-gameweek). `fpl_ep` is no longer scored there, and rows no longer require `ep_pre`.
- `choose_source(table) -> str` returns the lowest-MAE of `model` / `v2` / `last5_avg`. Ties go to `model`, then `v2`.
- `leak_check(conn, season) -> dict`, from archive `ep_pre` with minutes > 0:
  - `{"mae_incl": float, "mae_excl": float, "n": int, "big_ep_week": float, "big_ep_before": float, "n_big": int}`;
  - incl = the 4-gameweek points average including the week; excl = the 4 weeks before; big = players with 12+ points.
- `fpl_fair_check(conn) -> dict`: current season only, 1-gameweek only, on rows with non-NULL `ep_pre` (pre-deadline by Task 1).
  - Returns `{"methods": {"fpl_ep"|"v2"|"model"|"last5_avg": {"mae", "n"}}, "gws": [int], "excluded_gws": [int], "verdict": "too early to call" | "<best method>"}`.
  - The verdict is "too early to call" while `len(gws) < 5`.
- `write_report` sections:
  - archive 1-gameweek and 3-gameweek tables (3 methods);
  - "Leak check", with plain-English sentences around the two `leak_check` results per archive season;
  - "FPL's prediction, saved before kick-off", with `fpl_fair_check` results, the gameweeks, the players and the verdict.
  - Remove the old `current_season_check`, or fold it into `fpl_fair_check`.
